# 山间文昌殿 · 美术与工程迭代路线

## 固定设计意图

- 美术：温暖、静谧、治愈；旧木褐、朱红、石灰、亚麻白、深青、旧金。
- 空间：三开间文昌殿（12.6×9.6m），小前庭（12.6×7.2m），殿前古铜香炉，殿内中央文昌帝君，左侧求签、右侧挂福。
- 主角：中性国风小旅人，约 4.8 头身、1.55m，交领常服、束发、宽裤、布鞋。
- 神像：文昌帝君木雕彩绘坐像，含底座 2.85m，神像自身右手持笔、左手托卷，静态。
- 镜头：第三人称探索 + 仪式近景；无强烈镜头运动。
- V1：匿名单人，无支付、无聊天，个人愿望默认私有且仅保存在本地。

## 这份原型已经做了什么

程序化建筑、角色、神像、香炉、签筒、福牌架的视觉占位；角色移动、基础平面碰撞、键鼠和手机方向按钮；三类交互触发；上香分步流程、32 支原创签文和本地签号记录；六款福牌与 30 个固定挂点、私有 IndexedDB 记录。

上面描述的是 V1.1 原型基线。V1.4 已增加可播放骨骼动画的旅人 GLB（含右手/右肘/右腕与技术版 IK、握香道具绑定），V1.5 已增加静态文昌帝君 GLB 技术资产；两者尚不是最终美术。正式手指动画、真实火烟和专业角色造型仍待制作。

## V1.2 已实现的过渡动作

- 程序化旅人新增可转动的上半身和左右手臂：行礼前倾再复位，插香前伸并收回。
- 上香动作由渲染循环的时间线驱动，点击后需等待动作完成事件，不能直接跳到下一状态。
- 插香动作内的释放节点在标准化进度 0.76：手中香消失，炉口出现临时烟雾；成功写入 IndexedDB 后完成。
- 两个动作可在执行时取消而不写入，保存失败返回插香待重试。
- 未接入真正的 GLB 骨骼动画、IK、音效与连续角色寻路；见 [资产约定](./ASSET_CONTRACT.md)。

## V1.3 已完成的资产基础管线

- 新增 GLB 文件 opt-in 环境变量，角色与文昌帝君可以分别替换程序化网格。
- 旅人通过显式名称匹配 GLB 动画剪辑、验证 `IncenseGrip`，在渲染循环里用动作进度采样真实骨骼剪辑。
- 行礼和插香释放时序继续由逻辑控制器管理，烟雾与香可以挂载在导入模型的 `IncenseGrip` 上。
- 缺少资产或导出不符合契约时，保留此前验收的灰盒作为兜底。暂未收到实际 GLB，无法声称正式角色美术已完成。
- 资产命名、尺度、导入步骤见 [资产约定](./ASSET_CONTRACT.md) 和 README。

## V1.4 / V1.5 资产进展

- V1.4：旅人带蒙皮骨骼、待机/行走/行礼/插香动画；插香前步行接近、香炉周围 CCD IK 与胶囊碰撞约束；实际体验经本地测试和手工验收后合并。
- V1.5：新增静态文昌帝君 GLB 技术模型，高度 2.85m（含台座），自身右手执笔、左手托卷；按固定同源 GLB 路径加载，保留原有程序化神像回退。需在浏览器内检查正、侧、背造型与镜头。
- 后续重点是正式美术替换：角色服装与表情、木雕造像和建筑材质均需专业美术/文化审校，现有技术模型不能视为上线美术。

## 后续实施顺序

1. **真实 GLB 资产管线**：模型原点和方向、1 unit = 1 m、贴图压缩、分材质/LOD，先让神像和旅人替换程序化模型；检查正侧背比例、左右手持物和场景尺寸。
2. **角色与碰撞**：替换基础矩形阻挡为运动学角色控制器与 Rapier 碰撞系统；补充台阶、狭窄门道、墙角和镜头遮挡处理。
3. **动画事件**：待机、行走、转身、取香、点香、持香、行礼、插香、摇签、拾签、挂福；采用握持/释放事件来决定道具绑定，确保取消可恢复。
4. **仪式状态机增强**：引入更严格的阶段状态图与 session id，禁止重复提交；增加保存失败补偿逻辑与刷新恢复规则。
5. **Web 性能**：GLB 压缩、实例化福牌、烟雾降级、设备分档、相机运动选项、真实手机 FPS 和内存测试。
6. **声音、内容审校与 E2E**：背景风声、木器音效、道教文化审校、隐私与地区合规检查、跨浏览器完整操作验证。

## 首批完整验收场景

- 首次进入，玩家从 z=6.1 沿中轴线前进，绕过香炉，跨越台阶进入大殿。
- 在香炉附近选择上香，走完六步并恢复探索；重新打开网页后上香记录仍在。
- 在左侧求签台抽一支编号签，签诗与编号一致，刷新后历史不变。
- 在右侧写一条 60 字以内的心愿，使用可用挂点保存；刷新后仍显示、可删除。
- 手机横屏触控移动正常、弹窗不遮挡主操作；隐私记录不上传服务器。

## 技术限制与当前未验证项

GitHub Actions 自动验证因分钟额度用尽而关闭；由开发者 Mac 执行 `npm run ci:local`，并上传 `.local-ci/last-run.log`，测试及构建通过后再做浏览器真实画面验收。内置 GLB 采用可重复生成脚本和 Three.js GLTFLoader 测试，但构建成功不能代替美术/文化/移动性能检查。
