# 山间文昌殿 · 美术与工程迭代路线

## 固定设计意图

- 美术：温暖、静谧、治愈；旧木褐、朱红、石灰、亚麻白、深青、旧金。
- 空间：三开间文昌殿（12.6×9.6m），小前庭（12.6×7.2m），殿前古铜香炉，殿内中央文昌帝君，左侧求签、右侧挂福。
- 主角：中性国风小旅人，约 4.8 头身、1.55m，交领常服、束发、宽裤、布鞋。
- 神像：文昌帝君木雕彩绘坐像，含底座 2.85m，神像自身右手持笔、左手托卷，静态。
- 镜头：第三人称探索 + 仪式近景；无强烈镜头运动。
- V1：匿名单人，无支付、无聊天，个人愿望默认私有且仅保存在本地。

## 这份原型已经做了什么

程序化建筑、角色、神像、香炉、签筒、福牌架的视觉占位；角色移动、基础平面碰撞、键鼠和手机方向按钮；三类交互触发；上香分步流程、32 支原创签文和本地签号记录；六款福牌与 30 个固定挂点、私有 IndexedDB 记录。

这不是正式游戏 3D 资产的演示：尚无 GLB、骨骼动画、双手 IK、真实烟火和道具绑定。

## 后续实施顺序

1. **真实 GLB 资产管线**：模型原点和方向、1 unit = 1 m、贴图压缩、分材质/LOD，先让神像和旅人替换程序化模型；检查正侧背比例、左右手持物和场景尺寸。
2. **角色与碰撞**：替换基础矩形阻挡为运动学角色控制器与 Rapier 碰撞系统；补充台阶、狭窄门道、墙角和镜头遮挡处理。
3. **动画事件**：待机、行走、转身、取香、点香、持香、行礼、插香、摇签、拾签、挂福；采用握持/释放事件来决定道具绑定，确保取消可恢复。
4. **仪式状态机增强**：引入更严格的阶段状态图与 session id，禁止重复提交；增加保存失败补偿逻辑与刷新恢复规则。
5. **Web 性能**：GLB 压缩、实例化福牌、烟雾降级、设备分档、相机运动选项、真实手机 FPS 和内存测试。
6. **声音、内容审校与 E2E**：背景风声、木器音效、道教文化审校、隐私与地区合规检查、跨浏览器完整操作验证。

## 首批完整验收场景

- 首次进入，玩家从 z=6.1 沿中轴线前进，绕过香炉，跨越台阶进入大殿。
- 在香炉附近选择上香，走完六步并恢复探索；重新打开网页后上香记录仍在。
- 在左侧求签台抽一支编号签，签诗与编号一致，刷新后历史不变。
- 在右侧写一条 60 字以内的心愿，使用可用挂点保存；刷新后仍显示、可删除。
- 手机横屏触控移动正常、弹窗不遮挡主操作；隐私记录不上传服务器。

## 技术限制与当前未验证项

编写源码的执行环境无法访问 npm registry，因此无法在本地安装 React/Three.js 依赖、运行实际 Vite 构建或使用 WebGL 浏览器测试。已运行 Node 原生规则测试与 TypeScript 转译语法检查。将代码推入 GitHub 后，应由仓库 CI 执行依赖安装、构建，并补充浏览器端测试。
