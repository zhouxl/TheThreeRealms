# V1.2 游戏角色与仪式资产接口

本分支先让**可见动作和事件时序真实工作**。角色仍是程序化占位网格；正式 GLB 文件尚未提供，不能将占位网格称为骨骼动画成品。

## 模型单位与朝向

- **1 glTF unit = 1 m**，Y-up；角色本地前方为 **-Z**，向大殿移动时 rotation.y = 0。
- 角色高度 1.55m，根节点位于双脚所在地面；世界坐标以地板为准。
- 将来替换角色模型时，保留相同的根坐标与骨架朝向，不修改场景位置和存档。
- 文昌帝君坐像（含台座）2.85m，神像自身**右手执笔、左手托卷**，保持文化审校。

## 旅人骨骼与挂点（GLB 制作合同）

| 节点/剪辑 | 用途 |
|---|---|
| `Root` | 根运动，不要将行进位移烘进仪式动画 |
| `Hips` / `Spine` / `Head` | 行礼时腰背前倾和头部配合 |
| `Hand_L` / `Hand_R` | 双手动画和握持姿势 |
| `Elbow_R` / `Wrist_R` | V1.4 GLB 关键节点：肩肘与手腕控制，不得将香模型独立平移/旋转 |
| `IncenseGrip` | 香的附着点，方向统一为 Y-up |
| `IncenseTip` | 香头发光、烟雾发射点 |
| `Idle`, `Walk`, `TakeIncense`, `LightIncense`, `Bow`, `PlaceIncense` | 后续动画 Clip 名称 |

## 事件与取消

- `Bow` 完成，回到可点击「插香」阶段；不得在行礼按钮按下瞬间跳到插香。
- `PlaceIncense` 到达 `release` 事件：香从手部脱离、香炉显示临时香烟；触发于进度 **0.76**，将来可以由 GLB 事件标记替换。
- `PlaceIncense` 完成时才尝试写入 IndexedDB；事务提交成功才显示「完成」。
- 如失败，返回 `place` 可重试；取消仪式不得提交记录。
- 当前程序化动作时长：行礼 **1.8 秒**，插香 **2.4 秒**。仅为原型建议值。

## 视觉验收

1. 点击「行礼」后，旅人上身真实前倾并恢复，而非立即更换按钮。
2. 点击「插香」后，角色伸手靠近炉口，香和烟雾跟随动作；到达释放点后香进入炉中。
3. 玩家取消后，姿势、暂时道具和镜头恢复；重复点击不创建额外记录。
4. PC 与移动端可见，烟雾的粒子负载可降级。

后续分支接入真实 GLB 后应保留 `incenseMotion.ts` 的时间线合同，改由骨骼剪辑和动画事件响应，而不是写定时器猜测动画何时完成。

## V1.2 插香落点与可见性契约

- 香炉中心坐标通过 `incensePlacement.ts` 管理：世界坐标 `(0, 0, 3.2)`。
- 插香释放目标已更新为靠近旅人的灰面挂点 **`(0, 1.0, 3.5)`**（香底端，不是香头；香炉中心仍为 Z=3.2）。
- 角色进入仪式时站在 **`(0, 0, 4.6)`**，距香炉中心约 1.4 m。程序化上身绕 Y=0.7 轴旋转，持香底端在 0.76 释放点进入目标容差范围。
- 香释放后在香炉中显示实际 0.4 m 的立香模型和香头余烬，附着烟雾。未保存时显示一支临时预览，保存成功后按存档数量显示；取消不增加持久化数量。
- 最多渲染六支作为性能上限，超过六条历史记录不会绘制无数枝香。后续美术用固定挂点（`IncenseSlot_00…05`）替换这些程序化位置，不改变数据。

## V1.3 GLB 接入规则（已实现加载与回退，待真实模型）

- **不强制立即提供模型**：无环境变量时继续使用程序化旅人和神像。模型必须存放在 Vite 的 `public/` 目录，通过同源绝对路径配置。
- 将 `.env.example` 复制为 `.env.local`，填写 `VITE_TRAVELER_GLB_URL=/models/traveler.glb`、`VITE_DEITY_GLB_URL=/models/wenchang.glb`，然后重启 dev server。
- 仅允许 `/models/xxxx.glb` 一类同源静态路径；URL 无效、文件 404、模型加载异常或契约验证失败时，显示可玩的原有占位模型，并在 Console 输出原因。
- 旅人强制 GLB 节点名称：**`IncenseGrip`**（香的根端，随手部动画移动）。笔直香身沿局部 +Y 延伸，香头在锚点上方 0.48m；提供真正的手指动画时，不要再在模型中烘焙另一根香。
- 旅人强制剪辑名称：**`Idle`、`Walk`、`Bow`、`PlaceIncense`**。可选 `HoldIncense`、`TakeIncense`、`LightIncense`。当前 V1.3 只使用 `HoldIncense` 作为动作之间的站姿，不会循环播放一次性的取香/点香动作；后者在引入完整时间线事件后使用。缺少必需剪辑将回退灰盒；可选剪辑缺失则使用 `Idle`。
- 完整 GLB 剪辑的时长无需强制等于原型：通过逻辑动作的 0–1 进度采样，不与业务流程互相依赖。上香释放标记保持 0.76，签文/福牌存档结构不变。
- 旅人默认朝向 **-Z**，静态文昌帝君朝向 **+Z**；两者 Y-up，贴地原点；不要在网页里随意放大缩小模型来掩盖导出问题。
- 由于浏览器与设备上的蒙皮、动画混合和局部手腕旋转可能不同，导入实际模型后还需要人工检查：转身、行礼前倾、插香释放、烟雾向上、镜头遮挡、低端手机帧率。
- 当前版本尚无实时 IK 求解、模型性能自动分级、glTF 压缩与视觉回归截图；这些属于后续实物资产到位后的开发事项。

## V1.4 技术验证 GLB（可用来对照正式资产）

- 现已提交 `public/models/traveler-tech-demo.glb`（可在浏览器实际加载，不是仅有占位代码）。它是独立 glTF 2.0 **skinned mesh**、11 个关节和 5 个动画剪辑，但几何、材质、衣饰造型仍是技术验证级别。
- 模型生成器：`scripts/generateTravelerGLB.mjs`，运行 `npm run assets:demo` 会重新生成提交的二进制，测试在 CI 中比对两者完全一致。禁止用同名文件保存正式美术，否则下一次生成会覆盖。
- 未配置环境变量时默认载入技术 GLB；配置 `VITE_TRAVELER_GLB_URL=`（空值）才明确回退程序化网格。通过 `VITE_TRAVELER_GLB_URL=/models/traveler.glb` 可替换正式角色。
- 生成器使用 Root/Hips/Spine/Head/Shoulder_L/Hand_L/Shoulder_R/Hand_R/IncenseGrip 等命名节点，并把各肢体蒙皮到关节，五条动画通过 `AnimationMixer` 驱动。它用于验证模型加载、握香、行礼和插香的技术链路。
- **验收限制**：尚未在真实浏览器中完成人工美术/碰撞验收，动作自然程度不应作为最终美术质量评价。

## PR #4 视觉反馈修复（持续在 V1.4 分支）

- GLB 角色手持香的**香身、香头和烟雾**统一以世界 Y 轴保持竖直，不再继承腕关节导致的倾斜；相关工具与测试：`incenseTransforms.ts`。
- 插香时香从持续移动的手持节点沿平滑路径对准近侧灰面槽位，进度 0.76 交给香炉中的立香模型；取消不会增加已保存记录。
- 角色距香炉中心改为约 **1.4m**，降低模型与炉体重叠风险。技术模型仍非精细双手 IK，最后一段接触可能有手/道具间的微小分离，需正式骨骼动画进一步优化。
- 行礼使用较短的低头停留节拍，插香使用缓进、停顿、缓出，并带轻微身体前移与复位，替代匀速机械动作。
- 仪式期间 PC/手机可拖拽场景**环绕镜头**，桌面可用滚轮缩放；镜头仅移动视角，不改变角色面向或仪式状态。

## PR #4 新动作约定：真实手部控制（2026-11-07）

- 点击香炉即开始走向 `INCENSE_STAND=(0,4.6)`，使用角色真实速度、碰撞检测及侧路绕行；抵达后才显示「取香」。途中按 Esc 取消，不能留下香或记录。
- 默认技术 GLB 的右臂是 `Shoulder_R → Elbow_R → Hand_R → Wrist_R → IncenseGrip`，右手贴近香的**底端**；`Wrist_R` 负责让手握持的香朝上，香身和香头不再使用反向旋转校正。
- 插香轨迹是**先移动到目标上方，停顿，再向下**，释放点为动作归一化进度 0.76。插香时人物前迈一小步（足部约 4.0m 的 Z 位置），前庭站位仍保持与炉心约 1.4m 间隔。
- 每条记录按最多六个可到达的**近侧灰面槽位**选取实际落点，手部落点与最终香炉立香一致。
- 附加的 CCD 技术 IK 是过渡方案，采用骨骼旋转驱动肘/肩，不是最终商业级手指关节与脚底接触动画。正式美术资产仍需稳定的右肘/右腕节点，并验证动作与角色衣袖穿插。
- 上香期间的镜头可自由环绕、缩放，不改变角色方向、手腕插香目标及 IndexedDB 保存规则。
