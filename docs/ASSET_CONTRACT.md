# V1.2 游戏角色与仪式资产接口

本分支先让**可见动作和事件时序真实工作**。角色仍是程序化占位网格；正式 GLB 文件尚未提供，不能将占位网格称为骨骼动画成品。

## 模型单位与朝向

- **1 glTF unit = 1 m**，Y-up；角色本地前方为 **-Z**，向大殿移动时 rotation.y = 0。
- 角色高度 1.55m，根节点位于双脚所在地面；世界坐标以地板为准。
- 将来替换角色模型时，保留相同的根坐标与骨架朝向，不修改场景位置和存档。
- 文昌帝君坐像（含台座）2.85m，神像自身**右手执笔、左手托卷**，保持文化审校。

## 旅人骨骼与挂点（GLB 制作合同）

| 节点/剪辑 | 用途 |
|---|---|
| `Root` | 根运动，不要将行进位移烘进仪式动画 |
| `Hips` / `Spine` / `Head` | 行礼时腰背前倾和头部配合 |
| `Hand_L` / `Hand_R` | 双手持香、行礼、插香 |
| `IncenseGrip` | 香的附着点，方向统一为 Y-up |
| `IncenseTip` | 香头发光、烟雾发射点 |
| `Idle`, `Walk`, `TakeIncense`, `LightIncense`, `Bow`, `PlaceIncense` | 后续动画 Clip 名称 |

## 事件与取消

- `Bow` 完成，回到可点击「插香」阶段；不得在行礼按钮按下瞬间跳到插香。
- `PlaceIncense` 到达 `release` 事件：香从手部脱离、香炉显示临时香烟；触发于进度 **0.76**，将来可以由 GLB 事件标记替换。
- `PlaceIncense` 完成时才尝试写入 IndexedDB；事务提交成功才显示「完成」。
- 如失败，返回 `place` 可重试；取消仪式不得提交记录。
- 当前程序化动作时长：行礼 **1.8 秒**，插香 **2.4 秒**。仅为原型建议值。

## 视觉验收

1. 点击「行礼」后，旅人上身真实前倾并恢复，而非立即更换按钮。
2. 点击「插香」后，角色伸手靠近炉口，香和烟雾跟随动作；到达释放点后香进入炉中。
3. 玩家取消后，姿势、暂时道具和镜头恢复；重复点击不创建额外记录。
4. PC 与移动端可见，烟雾的粒子负载可降级。

后续分支接入真实 GLB 后应保留 `incenseMotion.ts` 的时间线合同，改由骨骼剪辑和动画事件响应，而不是写定时器猜测动画何时完成。

## V1.2 插香落点与可见性契约

- 香炉中心坐标通过 `incensePlacement.ts` 管理：世界坐标 `(0, 0, 3.2)`。
- 插香释放目标为香**底端**进入炉中灰面的 `(0, 1.0, 3.2)`，而不是香头。
- 角色进入仪式时站在 `(0, 0, 4.12)`。程序化上身绕 Y=0.7 轴旋转，持香底端在 0.76 释放点进入目标容差范围。
- 香释放后在香炉中显示实际 0.4 m 的立香模型和香头余烬，附着烟雾。未保存时显示一支临时预览，保存成功后按存档数量显示；取消不增加持久化数量。
- 最多渲染六支作为性能上限，超过六条历史记录不会绘制无数枝香。后续美术用固定挂点（`IncenseSlot_00…05`）替换这些程序化位置，不改变数据。
