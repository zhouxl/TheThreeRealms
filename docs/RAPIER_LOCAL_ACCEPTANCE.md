# V1.6 · Rapier 运动与碰撞本地验收

本次改造以 `main`（V1.4）为基础，开发分支 `feat/v1-6-rapier-character-camera`，与未合并的 V1.5 文昌神像 PR #5 独立。所有 GitHub Actions 自动触发保持关闭。

## 一键本地验证

```bash
git fetch origin
git switch --track origin/feat/v1-6-rapier-character-camera
nvm use
npm run ci:local
```

请上传 `.local-ci/last-run.log`，同时记录 `git rev-parse --short HEAD`。首次安装需允许 npm 下载 `@dimforge/rapier3d-compat`；不要自动放宽 `allowScripts` 安全审批。

## 物理与镜头实机验收

启动 `npm run dev`，访问 `http://localhost:5173/?physicsDebug=1` 查看物理体。黄色是静态障碍代理体，蓝色是门口三层台阶。

1. **初始移动**：玩家从院落 z=6.1 出发，按 W 沿中轴线穿过庭院。不得因为物理 WASM 启动而突然跳回初始点。
2. **香炉避让**：沿中轴向香炉移动，应在炉壁前停止，A/D 绕过两侧后恢复向前；不能通过香炉，也不能卡在其可见外部很远的地方。
3. **上台阶**：从中轴正前方连续 W，通过三层阶梯进入殿内；脚底应该稳定上升约 0.45m，不穿进台阶、不明显瞬移。
4. **前厅墙面/门柱**：向左右移动触碰墙、柱时应滑动，而不是穿墙；从中央通道可以自由进出。
5. **供案、左右功能桌**：从各侧绕行，接近但不能走穿供案、签筒底座或福牌架。
6. **自动上香**：从正前院落及殿内两侧分别点击香炉，角色沿可走路线到站位才触发“取香”；受阻时不会瞬移，提示重新选择开阔位置。
7. **镜头碰撞**：沿侧墙、门柱、屋内供案转动镜头，第三人称相机应在墙体前缩近，离开障碍恢复原距离；仪式拖动视角仍可用。
8. **回归功能**：完成上香、求签、挂福各一次，刷新后记录仍在；取消不会提交记录。
9. **手机端**：触摸移动、相机转动、门洞和台阶体验，记录 FPS、是否发烫或卡顿。WASM 首次初始化可能需要额外加载。

## 物理代理体的范围与限制

- 角色：直立胶囊，半径 0.23m、高 1.55m；带自动跨 0.22m 台阶和落地吸附。
- 障碍：根据灰盒坐标创建简单盒体/圆柱体，不是动态网格的逐三角面碰撞。
- 摄像机：对墙、柱、台面等代理体做视线段检测；此阶段尚无针对全套 GLB/透明装饰物的细粒度镜头碰撞。
- 导航：上香自动路线仍由既有路径规划产生，但每一步都由 Rapier 碰撞判定；无法到达时只提示，不传送。
- Rapier 初始化失败时控制台会给出原因，并回退到旧有的保守矩形碰撞，确保 V1 游戏仍可操作。
- **Do not merge** 直到本地 CI、实机视觉检查和基本三类仪式均完成。
